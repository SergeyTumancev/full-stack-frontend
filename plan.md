# Обучающий проект: Full-Stack Frontend



## Цель проекта

Построить современное веб-приложение с использованием актуального frontend-стека, чтобы:

- изучить Next.js (App Router, SSR/SSG),

- освоить базовый backend на Node.js + Express,

- научиться работать с базой данных,

- реализовать авторизацию с JWT,

- попробовать WebSocket,

- познакомиться с микросервисами и Module Federation.



Проект создаётся как учебный, но должен быть пригоден для демонстрации в резюме и на GitHub.



## Технологии

- Next.js (App Router, TypeScript)

- Node.js + Express

- PostgreSQL + Prisma

- JWT (access/refresh токены)

- WebSocket / Socket.IO

- REST API

- Module Federation (микрофронтенд)



## Общая архитектура

- Основной frontend: Next.js

- Основной backend: Express

- База данных: PostgreSQL

- Микросервис уведомлений: Node.js

- Админ-панель: отдельное приложение, подключённое через Module Federation



## Роль ИИ-агента

ИИ-агент выступает как наставник и код-ревьюер.



Не писать код за меня целиком.

Объяснять концепции.

Помогать разбирать ошибки.

Предлагать маленькие шаги.

Проверять мои решения и указывать на слабые места.



## План работы (10 шагов)



### Шаг 1. Инициализация Next.js проекта

- Создать проект через create-next-app.

- Использовать TypeScript, ESLint.

- Поднять локально.

- Понять структуру App Router.



### Шаг 2. Главная страница с SSR

- Создать список товаров на главной странице.

- Использовать серверный рендеринг.

- Понять разницу между серверными и клиентскими компонентами.



### Шаг 3. Страница товара

- Динамический маршрут /product/\[id].

- Получение данных по ID.

- Понять generateMetadata и динамическую маршрутизацию.



### Шаг 4. Подключение Express API

- Поднять отдельный Express-сервер.

- Реализовать GET /api/products.

- Связать Next.js с API.

- Разобраться с CORS.



### Шаг 5. База данных PostgreSQL

- Подключить Prisma.

- Создать модели User и Product.

- Наполнить базу тестовыми данными.

- Заменить локальный массив на данные из БД.



### Шаг 6. Авторизация JWT

- Создать страницу входа.

- Реализовать регистрацию и вход.

- Выдавать JWT-токен.

- Хранить токен в httpOnly cookie.



### Шаг 7. Защита маршрутов

- Создать страницу профиля.

- Проверять токен на сервере.

- Редиректить неавторизованных.

- Использовать middleware Next.js.



### Шаг 8. WebSocket уведомления

- Подключить Socket.IO или WebSocket.

- Отправлять событие "новый заказ" с backend.

- Показывать уведомление на frontend.



### Шаг 9. Микросервис уведомлений

- Поднять отдельный Node.js сервис.

- Настроить обмен данными между сервисами.

- Перевести уведомления в этот сервис.



### Шаг 10. Module Federation

- Создать отдельное приложение для админ-панели.

- Подключить его через Module Federation.

- Проверить совместную работу.



## Формат обучения

- Один шаг = 2–3 дня.

- В день: 30–60 минут на проект.

- Каждый шаг завершается рабочим результатом.

- ИИ-агент проверяет и даёт обратную связь.



## Критерии готовности каждого шага

Каждый шаг считается завершённым, если:

- код запускается без ошибок,

- можно воспроизвести результат локально,

- есть понимание, что именно сделано и зачем,

- ИИ-агент подтвердил, что логика корректна.



Дополнительно:

- после шагов 1–5: главная страница работает, данные приходят из БД,

- после шагов 6–7: вход и защита маршрутов работают,

- после шагов 8–10: уведомления и микрофронтенд работают.



## Как правильно задавать вопросы ИИ-агенту

Формулировать вопрос так, чтобы получить объяснение, а не готовый код.



Плохо:

"Напиши мне код для авторизации."



Хорошо:

"Я хочу реализовать авторизацию через JWT. Объясни, из каких шагов состоит процесс и с чего начать?"



Плохо:

"У меня ошибка, исправь."



Хорошо:

"Я получаю такую ошибку. Я попробовал это и это. Почему мой подход не работает? Что я упускаю?"



Плохо:

"Сделай проект за меня."



Хорошо:

"Дай мне маленькое задание на сегодня и проверь мой результат."
